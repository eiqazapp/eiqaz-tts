# مجلد التدريب — NileTTS 4h على Kaggle

يحتوي هذا المجلد على كل ما يخص جلسة تدريب النموذج: نواتا Kaggle الكاملتان
كما نُفّذتا، ومخرجات الجلسة الفعلية (الإعدادات والسجلات والمنحنى والعينات
الصوتية).

## المحتويات

```
training/
├── kaggle-kernels/
│   ├── niletts-4h-prep.py     ← نواة تجهيز البيانات (Kernel منفصل)
│   └── niletts-4h-train.py    ← نواة التدريب والتوليد (Kernel منفصل)
└── run-artifacts/
    ├── run_config.json        ← إعدادات التجربة كما نُفّذت فعليًا
    ├── training_curve.png     ← منحنى الخسائر عبر التدريب
    ├── train_log.csv          ← سجل التدريب خطوة بخطوة
    ├── val_log.csv            ← سجل التحقق الدوري
    ├── resource_log.csv       ← سجل استهلاك الموارد (GPU/RAM)
    ├── niletts-4h-train.log   ← السجل النصي الكامل للجلسة (705KB)
    ├── sanity_random_init.wav ← مخرج "فحص العقلانية" قبل بدء التدريب

        ├── egyptian_scratch/        ← توليد النموذج أثناء التدريب (نص مصري)
        ├── original_msa_reference/  ← المرجع الفصحي للمقارنة
        └── user_eval/               ← عينات التقييم النهائية
```

## ترتيب التنفيذ على Kaggle

1. **`niletts-4h-prep.py`** أولًا: يجهّز بيانات
   `KickItLikeShika/NileTTS-dataset` — فحص المقاطع، بناء مجمعات
   التدريب/التحقق (19,721 / 2,157 مقطعًا)، وحساب إحصاءات النبرة
   (pitch mean = 185.06، std = 79.50) المستخدمة في التكييف.
2. **`niletts-4h-train.py`** ثانيًا: يدرّب MixerTTS من الصفر بوصفة مؤلف
   `train_ms` (AdamW 1e-4 مع تناقص حتى 1e-5، ومُميِّز LSGAN تفعّل بعد
   2,000 خطوة إحماء)، يحفظ checkpoints دوريًا (`states_*.pth`)، يولّد
   عينات دورية للمتابعة، وينتهي عند استهلاك ميزانية 15,300 ثانية على GPU.

## نقاط الحفظ (Checkpoints)

النقطة النهائية المستخدمة في حزمة التوليد هي **`states_79590.pth`**
(الخطوة 79,590). ملفات الـcheckpoints كبيرة (الإجمالي ~223MB) ولا تُخزَّن
في git — احتفظ بنسختك المحلية من مخرجات Kaggle وضعها في
`../inference/checkpoints/` لتشغيل التوليد.
