# مجلد التحقق — إثبات سلامة حزمة التوليد

قبل تسليم حزمة التوليد المحلية، تم إثبات أنها **تنتج نفس مخرجات كود نواة
التدريب الأصلي تمامًا** — ليس نظريًا بل بقياس رقمي مباشر.

## الملف

- **`pkg_validate.py`** — سكريبت الموازاة الذي نُفّذ أثناء البناء: يحمّل
  نفس الـcheckpoint مرتين (مرة عبر كود نواة التدريب الأصلي ومرة عبر حزمة
  التوليد)، ويقارن: توكنز المدخل، الميل (spectrogram)، وملف WAV النهائي.

> ملاحظة: السكريبت كما هو يشتغل في بيئة البناء (يحوي مسارات مطلقة لملفات
  نواة التدريب الأصلية غير المضمّنة في المستودع). أُضمّن هنا كسجل موثّق
  للمنهجية والنتائج.

## النتائج المقيسة

| المقارنة | النتيجة |
|---|---|
| توكنز النص المُرمَّزة | متطابقة تمامًا |
| الميل (mel spectrogram) | **تطابق bit-by-bit** — فرق 0.0 |
| ملف WAV | ارتباط **1.000000** (تطابق تام) |
| موازاة مع عينة GPU نهائية من نفس الـcheckpoint (`egy_00.wav`) | نفس الطول (38,400 عينة) وارتباط **1.000** |

## اختبار البيئة النظيفة (محاكاة جهاز المستخدم)

حُقّق أيضًا أن الحزمة تعمل من الصفر في بيئة تحاكي جهاز المستخدم النهائي:

- Python نظيف + venv جديد بست مكتبات فقط (torch 2.5.1+cpu،
  onnxruntime 1.20.1، numpy 2.1.3، soundfile 0.13.1، einops 0.8.1،
  packaging 24.2).
- **CPU فقط** — بلا GPU وبلا أي ملفات Kaggle.
- تشغيل من مجلد خارجي: نجح بسرعة **1.9 ثانية/جملة**، وأعاد إنتاج الملف
  المرجعي المضمّن (`inference/samples/example_output.wav`) بارتباط
  1.000000 (فرق أقصى 6.1e-05 = فروق أنوية conv بين إصدارات torch —
  دون مستوى الإدراك السمعي).
