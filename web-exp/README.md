# تجربة محرك إيقاز داخل المتصفح (ONNX Runtime Web)

تشغيل محرك النطق **داخل المتصفح نفسه** (لا خادم بايثون للتوليد): النموذج
الصوتي MixerTTS بصيغة ONNX + المُصوِّت vocos + المُشكِّل catt_eo — كلها
تعمل في المتصفح عبر onnxruntime-web (WASM/CPU أو WebGPU)، مع **محاكاة بث
حقيقية** للنموذج اللغوي (النص يصل على دفعات والصوت يبدأ فورًا من أول
جملة مكتملة) و**مقاطعة فورية** حقيقية.

> هذا التطبيق **مستقل تمامًا** عن واجهة الإنتاج القديمة
> (`inference/webapp.py`) — لم يُمَس أي ملف من مسار الإنتاج.

<a id="ماذا-يحتوي"></a>
## ١) ماذا يحتوي هذا المجلد

| الملف | الدور |
|---|---|
| `index.html` + `app.js` | الواجهة العربية RTL + محرك التوليد/البث/المقاطعة |
| `textpipe.js` | **منفذ JS لخط معالجة النص الإنتاجي** (تنظيف + علامات {ق}/{ء}/{ج} + طبقة القاف + باكوالتير + التفقيم + الترميز) — مكافئ بايثون **توكن-بموكن** (مثبت بالاختبارات) |
| `catt.js` | منفذ JS للمُشكِّل catt_eo — مخرجاته **مطابقة بايثون** (مثبت) |
| `models/` | نماذج ONNX (تُبنى محليًا — لا تُرفع لـgit) + `textpipe_data.js` (معاجم القاف مولَّدة من infer.py نفسه) |
| `vendor/ort/` | onnxruntime-web 1.30 محليًا (يعمل بلا إنترنت على الشبكة المحلية) |
| `serve.py` | خادم الشبكة المحلية (+HTTPS اختياري + ترويسات عزل المصدر) |
| `tests/` | اختبارات التكافؤ والـE2E داخل متصفح حقيقي |

<a id="المتطلبات"></a>
## ٢) المتطلبات والتثبيت

- **الحاسوب**: Windows (أو Linux/macOS للتطوير) + Python 3.12 (64-bit)
- حزمة الاستدلال الأصلية مثبتة (انظر `inference/README_INSTALL_WINDOWS.md`)
- ثم إضافات التصدير (مرة واحدة، من جذر المستودع):

```bat
python -m pip install -r inference\onnx\requirements-onnx.txt
```

- checkpoint الإنتاج في مكانه: `inference\checkpoints\states_79590.pth`
- **للاختبارات الآلية فقط**: Node.js 18+ (لازم لتشغيل اختبار تكافؤ خط
  النص خارج المتصفح — نفس الاختبار يعمل داخل المتصفح عبر
  `browser_e2e.py` بدون Node) + Playwright لاختبار E2E.

<a id="بناء-النماذج"></a>
## ٣) بناء النماذج — أمر واحد على Windows

```bat
cd inference\onnx
build_models.bat
```

ينفّذ تلقائيًا ويطبع نتائج كل خطوة:
1. `export_onnx.py` — تصدير FP32 + **فحص تكافؤ mel مقابل PyTorch** على
   توكنز النصوص الذهبية (يجب أن يطبع `PASS 14/14`).
2. `quantize_onnx.py` — بناء FP16 / INT8-dynamic / INT8-static + قياس
   التكافؤ لكل نسخة + `manifest.json` (أحجام + SHA-256).
3. `gen_textpipe_data.py` — معاجم القاف + مراجع التكافؤ للمتصفح.
4. `bench_onnx.py` — قياس أداء الخادم (TTFA/RTF) لكل نسخة.

> **في بيئة بلا checkpoint حقيقي** (تطوير): ولّد checkpoint عشوائيًا بنفس
> البنية أولًا: `python make_sanity_ckpt.py` ثم
> `python export_onnx.py --checkpoint states_sanity_random.pth`.
> الصوت سيكون ضجيجًا (معلن في الواجهة بشارة تحذير صفراء) — للتحقق
> الميكانيكي فقط.

<a id="التشغيل-على-الحاسوب"></a>
## ٤) التشغيل على الحاسوب

```bat
cd web-exp
python serve.py
```

سيطبع:

```
  من الحاسوب   : http://localhost:8777
  من الهاتف    : http://192.168.x.x:8777      ← عنوان IP الفعلي لجهازك
  إيقاف الخادم: Ctrl+C
```

افتح الرابط في Chrome أو Edge. لا حاجة لأي إنترنت — كل شيء محلي
(النماذج ومكتبة onnxruntime مضمّنة في المجلد).

خيارات إضافية:

```bat
python serve.py --port 9000          REM منفذ مختلف
python serve.py --host 127.0.0.1     REM جهازك فقط (لا هاتف)
python serve.py --https              REM للمتصفحات المتطلبة سياقًا آمنًا
```

<a id="الفتح-من-الهاتف"></a>
## ٥) الفتح من الهاتف — الشبكة المحلية (Wi-Fi نفسها)

1. اجعل الهاتف والحاسوب على **نفس شبكة Wi-Fi** (وليس شبكة الضيوف —
   كثير من شبكات الضيوف تعزل الأجهزة عن بعضها).
2. شغّل الخادم كما أعلاه — انسخ سطر «من الهاتف» المعروض بعنوان IP
   **الفعلي لجهازك** (لا تخمينًا). للتأكد يدويًا في Windows:

   ```bat
   ipconfig
   REM ابحث تحت «Ethernet adapter» أو «Wireless LAN adapter Wi-Fi»:
   REM    IPv4 Address . . . . . . . . . . . : 192.168.1.23   ← هذا عنوانك
   ```

3. منح منفذ الخادم عبر جدار حماية Windows (مرة واحدة، بأمر **مسؤول**
   في PowerShell — يقتصر على المنفذ فقط لا كل شيء):

   ```powershell
   New-NetFirewallRule -DisplayName "Eiqaz Web Exp 8777" -Direction Inbound -Protocol TCP -LocalPort 8777 -Action Allow
   ```

   (استبدل 8777 بمنفذك إن غيّرته. للحذف لاحقًا:
   `Remove-NetFirewallRule -DisplayName "Eiqaz Web Exp 8777"`)
4. افتح `http://<عنوان-IP>:8777` في متصفح الهاتف — Chrome على Android
   أو Safari على iPhone.
5. **ملاحظة تشغيل الصوت على الهاتف**: المتصفحات تمنع الصوت قبل لمسة
   من المستخدم — اضغط أي زر («توليد الصوت» / «محاكاة البث») وهو تفاعل
   كافٍ لتفعيل الصوت.
6. لو لم يفتح الرابط: راجع [حل المشكلات](#حل-المشكلات) (جدار حماية /
   عزل شبكة الضيوف / منفذ مشغول).

> **تنبيه WebGPU**: على HTTP عبر عنوان IP، معظم المتصفحات تعتبر
> السياق غير آمن فلا يعمل WebGPU (يعمل WASM بسرعة جيدة عادة). لتجربة
> WebGPU من الهاتف انتقل للقسم التالي (HTTPS).

<a id="تشغيل-https"></a>
## ٦) HTTPS (لتجربة WebGPU من الهاتف)

بعض الميزات (WebGPU، وأحيانًا خيوط WASM المتعددة) تتطلب «سياقًا آمنًا»:
`https://` أو `localhost`. خطوات عملية بلا نشر خارجي:

```bat
cd web-exp
python serve.py --https
```

- إن وُجد `openssl` في جهازك (يأتي مع Git for Windows غالبًا:
  `C:\Program Files\Git\usr\bin\openssl.exe` — أضف مجلده إلى PATH أو
  مرّر المسار كاملًا) سيولّد الخادم شهادة محلية تلقائيًا صالحة 825
  يومًا لعنوان IP لجهازك، ويطبع رابط `https://<IP>:8777`.
- **على الحاسوب**: المتصفح سيعرض «تحذير اتصال غير خاص» — اضغط
  «خيارات متقدمة ← المتابعة» (كافٍ لتجربة WebGPU على localhost/Chrome
  وEdge غالبًا يعملان مع التحذير).
- **على الهاتف**: شهادة موقّعة ذاتيًا غير موثوقة تلقائيًا. خياران:
  - **أ (الأسهل — تجربة عملية):** افتح رابط HTTPS من الهاتف وقبل
    التحذير إن سمح المتصفح (Chrome على Android يسمح «المتابعة» غالبًا؛
    Safari على iOS أكثر صرامة).
  - **ب (ثقة كاملة):** استخدم [mkcert](https://github.com/FiloSottile/mkcert)
    على الحاسوب: يولّد شهادة وجذرًا محليًا؛ ثبّت ملف الجذر على الهاتف
    (Android: الإعدادات ← الأمان ← تثبيت شهادة CA؛ iPhone/iPad: ملف
    وصف الجذر من Safari ثم تفعيله في الإعدادات) ثم مرّر للخادم:

    ```bat
    python serve.py --https --cert cert.pem --key cert-key.pem
    ```

  - تذكر حذف قاعدة جدار الحماية وإيقاف الخادم بعد انتهاء الاختبار.

**بدائل لا نستخدمها هنا**: الأنفاق العامة (ngrok وأمثالها) تجعل
التطبيق متاحًا خارج شبكتك وتنقل ملفات النماذج (100MB+) عبر طرف ثالث —
لا حاجة لها ولا ننصح بها هنا.

<a id="استخدام-الواجهة"></a>
## ٧) استخدام الواجهة وقراءة القياسات

- **النموذج**: FP32 (مرجع) / FP16 / INT8-dyn / INT8-static — الحجم
  والتكافؤ معروضان بجوار كل نسخة. الواجهة تعرض تحذيرًا أصفر إن كانت
  النماذج بأوزان sanity.
- **مسار التنفيذ**: تلقائي (WebGPU ثم WASM مع تسجيل الرجوع) /
  WASM إلزامي (مسار CPU الحقيقي) / WebGPU إلزامي (يفشل بصوت عالٍ إن
  غير متاح — لا صمت).
- **المتحدث/اللهجة/السرعة**: كما في واجهة الإنتاج (0 ذكر / 1 أنثى).
- **توليد كامل**: يقسم النص تلقائيًا (نفس سياسة webapp) ويوحّد النبرة
  غير السببية (RMS وسيط + تلاشي 8ms + فاصل 220ms + تطبيع ذروة واحد)
  — مطابق للإنتاج.
- **محاكاة البث**: اضبط حجم دفعة النص (كلمات) والفاصل الزمني، اضغط
  «بدء محاكاة البث». النص يظهر يصل دفعة-دفعة (أخضر = الوصول الحالي)
  وكل جملة مكتملة تُولَّد وتُشغَّل **فورًا** دون انتظار بقية الرد.
- **المقاطعة**: زر أحمر — يوقف الصوت فورًا، يرفض الدفعات المتأخرة
  (آلية epoch)، ويسمح بطلب جديد **بلا إعادة تحميل الصفحة**.
- **القياسات**:
  - **TTFA**: من وصول أول دفعة نصية حتى جدولة أول عينة صوت مسموعة —
    **يجب أن يكون أقل من زمن وصول النص كاملًا** (هذا جوهر البث).
  - **RTF**: زمن التوليد ÷ مدة الصوت (أقل من 1 = أسرع من الزمن الحقيقي).
  - زمن المقاطعة بالمللي ثانية يظهر بعد كل مقاطعة.
- **لوحة التشخيص** (أسفل الصفحة): إصدار التطبيق وonnxruntime، توفر
  WebGPU فعليًا، مسار التنفيذ المطلوب/الفعلي، أزمنة تحميل كل جلسة،
  استهلاك ذاكرة JS (كروم فقط)، وأي أخطاء.

<a id="قياس-الأداء"></a>
## ٩) قياس الأداء

- **داخل المتصفح**: القياسات تظهر تلقائيًا في الواجهة (TTFA/RTF/مدد)
  لكل تشغيل — انسخها للتقرير.
- **على الخادم (بايثون)**:

  ```bat
  cd inference\onnx
  python bench_onnx.py          REM كل نسخ ONNX: TTFA/RTF/تحميل
  python bench_baseline.py      REM المسار الأصلي PyTorch للمقارنة
  ```

  كلاهما يكتب JSON بالنتائج ويعمل على نفس النصوص الذهبية
  (`golden_texts.json`) — نفس النصوص لكل النسخ دائمًا.

<a id="إيقاف-الخادم"></a>
## ١٠) إيقاف الخادم

اضغط **Ctrl+C** في نافذة الطرفية التي تشغّل `serve.py` — لا شيء يبقى
شغالًا خلفك (لا خدمات ولا منافذ مفتوحة). لو أضفت قاعدة جدار الحماية
وأردت إزالتها:

```powershell
Remove-NetFirewallRule -DisplayName "Eiqaz Web Exp 8777"
```

<a id="حل-المشكلات"></a>
## ١١) حل المشكلات الشائعة

| المشكلة | السبب الأرجح | الحل |
|---|---|---|
| «لا يوجد manifest» في الواجهة | لم تُبنَ النماذج | شغّل `inference\onnx\build_models.bat` |
| الهاتف لا يفتح الرابط | جدار حماية Windows | أمر `New-NetFirewallRule` أعلاه (أو اسمح لتطبيق Python من خلال Windows Defender Firewall) |
| الهاتف لا يفتح الرابط (٢) | شبكة ضيوف معزولة | بدّل إلى شبكة Wi-Fi الرئيسية، أو فعّل «AP isolation = off» في الراوتر |
| الهاتف لا يفتح الرابط (٣) | IP خاطئ | استخدم IP المطبوع من serve.py نفسه (لا من ipconfig لكرت آخر) |
| WebGPU لا يعمل من الهاتف | سياق غير آمن (HTTP عبر IP) | استخدم `--https` (§٦) أو اختبر WASM — يعمل دائمًا |
| الصوت لا يبدأ على الهاتف | سياسة التشغيل التلقائي | المس الشاشة/اضغط زرًا أولًا (المتصفح يطلب تفاعلًا) |
| بطء WASM واضح | خيط واحد (لا عزل مصدر) | خدمة serve.py ترسل COOP/COEP تلقائيًا؛ إن استخدمت خادمًا آخر أضف الترويسات |
| «رمز غير معروف» أو انحراف نطق | textpipe_data.js قديم | أعد `gen_textpipe_data.py` بعد أي تعديل على infer.py |
| فشل تصدير ONNX | checkpoint قديم بلا net_config | حدّث checkpoint من مخرجات Kaggle الأخيرة |
| صفحة الهاتف تتعطل عند تحميل 78MB (catt) | ذاكرة الهاتف | عطّل «تشكيل تلقائي» واستخدم نصًا مشكولًا مسبقًا |

<a id="الحدود-الصادقة"></a>
## ١٢) الحدود الصادقة لهذه التجربة

- **الجودة تُقاس على جهازك بالأوزان الحقيقية**: كل القياسات في بيئة
  التطوير (إن وُجدت) بأوزان عشوائية (sanity) — تعمل الآلية كاملة لكن
  الصوت ضجيج. الواجهة تعلن ذلك بشارة تحذير.
- **توحيد النبرة في وضع البث سببي** (وسيط الجهارة الجاري) بينما وضع
  «توليد كامل» مطابق للإنتاج تمامًا (وسيط كل المقاطع) — لأن مستقبل
  البث مجهول لحظة تشغيل كل مقطع. الفرق موثق ومحدود الأثر.
- **التشكيل catt يعمل على مستوى المقطع/الجملة** داخل البث (جملة مكتملة)
  — مطابق لمسار webapp متعدد المقاطع نفسه، وليس على النص الكامل دفعة
  واحدة.
- **INT8 على WASM**: آلية التشغيل مثبتة لكن حكم الجودة النهائي يحتاج
  أذنك على الأوزان الحقيقية (راجع جدول التكافؤ في manifest.json).
- **هاتف فعلي**: اختبارات هذه البيئة تمت على Chromium حقيقي (حاسوب) —
  اختبر بنفسك من هاتفك عبر الخطوات أعلاه وسجل النتيجة في
  `docs/DEVICE_TEST_LOG.md`.
